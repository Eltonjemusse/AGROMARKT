2. ALTERAÇÕES DA FASE 2A.3

- Cliente Prisma 5.22.0 atualizado com geração isolada, sem carregar o .env
  do projeto nem ligar a uma base de dados. Artefactos gerados em
  backend/node_modules/.prisma/client, ignorados pelo Git.
- Campos estruturados integrados nos controladores de produtos/encomendas.
  Quantidade, preço unitário e total novos entram/saem como strings decimais.
- Cálculos estruturados usam validadores existentes, precisão 40 e
  ROUND_HALF_UP apenas no total final. Valores fora dos limites, excesso
  significativo de escala e total final zero são rejeitados.
- Novas escritas estruturadas exigem quantidade, unidade, preço e moeda
  coerentes. kg/litro permitem frações; unidade/saco exigem inteiros.
- Contratos legados preservados temporariamente. Dados contraditórios entre
  formatos são rejeitados. Projeções antigas são sincronizadas; alterações
  comerciais apenas pelos campos antigos de produtos estruturados são
  rejeitadas para evitar dados desatualizados.
- Encomendas estruturadas obtêm comprador da autenticação e vendedor,
  unidade, moeda, preço e nome do produto no servidor. Guardam snapshots
  imutáveis e versão de cálculo.
- Editar o produto ou alterar o estado da encomenda não modifica snapshots.
  Tentativas de enviar/modificar campos de snapshot são rejeitadas.
- Produtos antigos continuam consultáveis. Pedidos estruturados sobre
  produtos incompletos devolvem HTTP 409 claro. Nenhuma unidade ou dado
  histórico é inventado; não há interpretação automática do texto antigo.
- Permissões das fases 1A/1B mantidas. Pendentes não reservam, comparam ou
  descontam disponibilidade. Stock e novas transições não foram implementados.

4. ERROS ENCONTRADOS E CORRIGIDOS

- A primeira tentativa de invocar diretamente o ficheiro JavaScript do
  gerador Prisma bloqueou no Windows. A tentativa terminou sem sucesso e a
  remoção da pasta temporária encontrou EBUSY. O script foi corrigido para
  invocar o gerador explicitamente através de Node e não ocultar a falha
  original com o erro de limpeza. A geração seguinte terminou com sucesso;
  os testes HTTP usaram o cliente atualizado. Não houve acesso a dados reais.
- Uma verificação de sintaxe usou caminhos com backend duplicado, causando
  MODULE_NOT_FOUND. Os caminhos foram corrigidos e a verificação passou.
- O Git apresentou avisos de acesso ao ficheiro global de exclusões e de
  normalização LF/CRLF. Não eram falhas dos testes nem erros de espaços.

Não houve falhas nos testes locais ou de persistência executados.
